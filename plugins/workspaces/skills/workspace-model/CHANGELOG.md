## Changelog

- **2026.09.24** — Initial version. Company-neutral rules for identity, filesystem roots,
  environment isolation, cross-workspace read/write boundaries, and one-paste handoffs,
  drawn from the workspace-model design spec sections 3-6 and 9. Installed as a personal
  marketplace in every Claude account, home and client alike.
- **2026.11.19** — Section 6 gains "Source-control sign-in: home and client differ, on purpose": a shared per-username credential slot is shared by every workspace on a machine that signs in as that username; home workspaces use the interactive sign-in in that slot, a client workspace uses a fine-grained token with exactly one resource owner (the client's organization) in its own config folder as the top-level token entry, pasted at the tool's own prompt; a per-client git config pins git the same way and blocks any route that would send other organizations' URLs out under the operator's identity; the three checks to make after every client sign-in; and what never to do (sign out the shared username, sign in under the default folder, run the global git-credential setup, copy the shared token into a client folder). Section 5's identity-check description adds the client token-source check. Company-neutral wording; names no company, account, machine or person. Basis: a client sign-in overwrote a shared slot and broke the home workspaces on one machine (2026-11-19). Requested by the operator.
